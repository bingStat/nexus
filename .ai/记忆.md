# Nexus 记忆与偏好准则

## 当前偏好

1. 单一安装脚本：只维护根目录 `install.sh`。
2. 设备鉴权不用共享 token；使用每设备 Nexus 专用 Ed25519 API identity。
3. SSH trust 使用独立 Nexus SSH key，并通过 Registry 发布 approved 设备 public keys。
4. 新设备必须 pending -> approved，不自动信任。
5. 报告成功必须有真实验证：job completed、exit_code、可验证 output。
6. 旧设计、旧脚本、旧验收材料删除后，只在 `其他目标.md` 保留核心思想；主线只保留 v3 和 council 机制。

## 红线

- 不打印或提交 private key、admin key、ChatGPT bearer token、dashboard password、cookie 或 MFA 材料。
- 不未经确认执行重启、断网、firewall、Tailscale、Cloudflare、磁盘、数据库删除等高风险操作。
- 不把 transport fallback 解释成 target 改派；逻辑目标必须保持不变。
- 不把 VSC inbound SSH 描述为已解决；HPC SSH certificate policy 需要独立处理。

## 当前特殊事实

- VSC 已加入 tailnet，IP `100.123.110.53`，但为 userspace networking；VSC outbound SSH 需用 `tailscale nc` / `ProxyCommand`。
- Windows OpenSSH 使用 Nexus key 时建议加 `IdentitiesOnly=yes`。
- N1 Dropbear 需要 `/etc/dropbear/authorized_keys`，不能只更新 `/root/.ssh/authorized_keys`。

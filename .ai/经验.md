# 经验与排障成功路径 (Troubleshooting & Lessons Learned)

本文档记录在 Nexus 部署与运行过程中遇到的技术故障及其权威解决路径。

---

## 排障案例归档

### 案例 4：Cloudflare 隧道迁移与 `tunnel is not locally managed`
- **现象**：将本地托管的隧道迁移到 Cloudflare Zero Trust (Remote Managed) 后，尝试在本地使用 `cloudflared tunnel route` 或 `config.yml` 运行报错 `Bad Configuration: tunnel is not locally managed`。
- **解决路径**：
  迁移成功后，本地配置文件即刻作废。必须在网页控制台（Zero Trust）复制 `ey...` 开头的 Token，然后在目标机器上运行 `cloudflared service install <Token>`，将隧道作为系统服务接管。遇到旧配置干扰，可先执行 `rm -rf /etc/cloudflared`。

### 案例 5：ThinkCenter 访问 GitHub 超时与透明代理
- **现象**：`git clone https://github.com/...` 和 `ghproxy` 国内镜像源均因为网络连接失败，导致在 ThinkCenter 上的大体积代码拉取超时。
- **解决路径**：
  直接挂载家庭局域网内的软路由（N1）透明代理（例如 `192.168.31.88:7890`）：
  ```bash
  http_proxy=http://192.168.31.88:7890 https_proxy=http://192.168.31.88:7890 git clone --depth 1 <url>
  ```
  （配合 `--depth 1` 浅克隆大幅缩减体积避免大仓超时被 Agent 误杀）。


### 案例 1：Ubuntu 24.04 `PEP 668` 全局 pip 安装拦截
- **现象**：在 ThinkCenter 上通过 `pip3 install` 安装 `mcp` 时提示 `error: externally-managed-environment`。
- **解决路径**：
  在 `deploy_thinkcenter.py` 中添加 `--break-system-packages` 或虚拟环境 `/opt/nexus/venv`，确保依赖库顺利写入：
  `python3 -m pip install --break-system-packages mcp fastapi uvicorn requests`

### 案例 2：Windows 控制台 `cp1252` 编码 UnicodeEncodeError 崩溃
- **现象**：当 `deploy_thinkcenter.py` 输出包含 `●` 或 `♥` 等 Unicode 符号时，Windows PowerShell 报 `UnicodeEncodeError: 'charmap' codec can't encode character`。
- **解决路径**：
  在所有部署脚本与 CLI 入口顶部强制添加字符流重定向：
  ```python
  import sys
  if hasattr(sys.stdout, 'reconfigure'):
      sys.stdout.reconfigure(encoding='utf-8', errors='replace')
  ```

### 案例 3：MCP 模块跨目录导入 ModuleNotFoundError
- **现象**：在根目录运行 `python3 -m mcp_server.app` 时报 `ModuleNotFoundError: No module named 'mcp_server'`。
- **解决路径**：
  在 `server.py` 与 `app.py` 中插入绝对路径解析：
  ```python
  import os, sys
  sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
  ```
  并在 systemd 配置中加入 `Environment="PYTHONPATH=/opt/nexus"`。

## 2026-08-06 结项排障案例

### 案例 6：Windows Agent 心跳在线但 worker 不领取任务

- **现象**：`victus` 心跳持续更新，但最小 PowerShell 任务保持 `pending`。
- **根因**：旧任务超时后，子孙进程继承输出管道，`communicate()` 无界等待并占满 worker。
- **解决**：独立进程组、`taskkill /T /F`、第二次 `communicate(timeout=5)`、必要时关闭本地管道；重启 `NexusAgent` 计划任务。
- **验收**：10/10 快速任务完成，3 秒超时返回 `124`，之后任务立即成功。

### 案例 7：Playwright Extension 显示 Invalid token

- **现象**：扩展拒绝 MCP Bridge，显示 `Invalid token provided`。
- **根因**：secret 文件保存了完整 `NAME=value`，启动器再次赋值，变量值变成重复前缀。
- **解决**：启动器只提取第一个等号右侧原始 Token；不在日志显示 Token。

### 案例 8：设备状态全部误判 offline

- **现象**：刚更新心跳仍显示约 8 小时离线。
- **根因**：Oracle 使用 `time.mktime()` 将 UTC 字符串按本地时区解析。
- **解决**：使用 UTC 时间转换 (`calendar.timegm`) 计算 `age_seconds`。

### 案例 9：Claude 已回复但 Adapter 记录 timeout

- **现象**：Claude 页面已经生成回答，但 MCP `tools/call` 超时。
- **根因**：用整个页面文本稳定性判断完成，动态 UI 持续变化。
- **解决**：Provider 专用检测；抓取新增 assistant/article 节点，并等待 streaming 标记消失。

# Nexus 经验与排障路径

## 1. 判断成功必须看 job result

`systemctl active` 只能说明服务进程在，不能说明 Nexus command path 可用。最终验收必须看：

- job 被提交；
- target agent claim；
- job completed；
- exit_code 正确；
- output 可验证。

## 2. Registry 分裂要尽早处理

本机 registry 和 Oracle/global registry 曾分别保存不同设备，导致 SSH key 发布和 broker 验签视图不一致。最终应以 Oracle/global registry 为权威，所有正式设备都注册并批准到同一 registry。

## 3. Cloudflare 1010 不等于 broker 挂了

从某些本地 Python/脚本访问公网 broker 可能被 Cloudflare 规则拦截并返回 1010。验证 broker 时优先从 broker 所在机器本机接口检查，再判断公网入口策略。

## 4. Windows JSON BOM

PowerShell `Set-Content -Encoding UTF8` 可能写出带 BOM 的 JSON。Agent 配置读取应使用 `utf-8-sig`，否则会出现：

```text
JSONDecodeError: Unexpected UTF-8 BOM
```

## 5. Windows OpenSSH key 选择

Windows 作为 SSH 源节点时，如果不加 `IdentitiesOnly=yes`，OpenSSH 可能先尝试过多默认 key，导致目标返回：

```text
Too many authentication failures
```

## 6. N1 / OpenWrt 特殊点

- BusyBox 命令参数和 GNU 工具不完全兼容；
- Dropbear 使用 `/etc/dropbear/authorized_keys`；
- 同步 SSH key 时不能只写 `/root/.ssh/authorized_keys`；
- 复杂脚本通过 Nexus heredoc 下发比依赖本地 SSH 更可靠。

## 7. VSC Tailscale 特殊点

VSC 使用用户态 Tailscale：

```text
~/.local/bin/tailscale
~/.local/state/tailscale/tailscaled.sock
--tun=userspace-networking
```

因此普通 `ssh 100.x` 不走 tailnet 路由。应使用：

```bash
ssh -o ProxyCommand="$HOME/.local/bin/tailscale --socket=$HOME/.local/state/tailscale/tailscaled.sock nc %h %p" ...
```

VSC inbound SSH 受 KU Leuven HPC SSH certificate policy 限制，不能用普通 Nexus public key 解决。

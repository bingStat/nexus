# Nexus 技术细节演进

## 当前 v3 决策

Nexus v3 采用三层控制面：

```text
Registry -> Broker -> Agent
```

- Registry 只保存 approved 设备、API public key、SSH public key 和元数据。
- Broker 只做 job queue、claim、complete 和签名验真。
- Agent 只领取自己的任务，执行后签名回执。

## 为什么替代旧 token

旧 token 模式的问题是复制、轮换、泄露面和设备撤销都不清晰。v3 只把公钥交给服务器，私钥永远留在设备本机；撤销设备只需要改 Registry 状态。

## 为什么 SSH key 与 API identity 分离

API identity 用于 HTTP 请求签名；SSH identity 用于机器间登录。两者生命周期、用途和暴露面不同，不能混用。

## 为什么不使用 cron 同步 SSH keys

SSH key 集群增长是低频事件。安装或批准新设备时触发一次同步即可，避免 cron 在故障、断网或 registry 异常时持续扰动 authorized_keys。

## VSC userspace Tailscale

VSC 已有用户态 Tailscale，但 `--tun=userspace-networking` 不创建系统路由。因此普通 `ssh 100.x` 失败不代表未入网；应通过：

```bash
ssh -o ProxyCommand="$HOME/.local/bin/tailscale --socket=$HOME/.local/state/tailscale/tailscaled.sock nc %h %p" ...
```

VSC inbound SSH 受 KU Leuven HPC SSH certificate policy 限制，不能靠 Nexus public key 单独解决。

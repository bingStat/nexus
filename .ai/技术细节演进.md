# 技术细节演进与设计理由 (Architecture Evolution & Design Rationale)

本文档记录 Nexus 系统的演进历程、设计决策依据与性能测评指标。

---

## 1. 架构演进路线

1. **v1.0 (Direct SSH / Webhook)**:
   - 依赖暴露 SSH 端口或依赖 HTTP 同步连接。受限于 30 秒 HTTP 超时壁垒，无法运行长时任务。
2. **v2.0 (Supabase REST + CAS Pull Protocol)**:
   - 引入 Supabase Cloud REST 数据库，采用 `pending` -> `running` -> `completed` 异步 CAS 锁状态机，彻底规避超时问题。
3. **v3.0 (FastMCP Dual Transport Architecture)**:
   - 引入 FastMCP 协议层 (`mcp_server/`)。
   - 实现 **STDIO 模式**（本地 CLI）与 **HTTP/SSE 模式**（`nexus.bings.app/sse`）双模传输。

---

## 2. 设计理由 (Design Rationale)

### 为什么选择 FastMCP + Supabase Cloud？
- **可靠性**: Supabase Cloud 保证节点心跳与命令在云端持久化，即使物理机器临时断网或关机，任务也不会丢失。
- **扩展性**: FastMCP 为 ChatGPT、Claude、Cursor、Antigravity 等任意现代 AI 客户端提供了标准化的 Tool 交互接口。

---

## 3. 性能测试指标 (Performance Benchmarks)

| 指标 | 测量值 | 评级 |
| :--- | :--- | :--- |
| **Command Enqueue Latency (POST /commands)** | < 18 ms | 极优 |
| **Agent Pull Cycle (POLL_SEC)** | 2.0 s | 均衡 |
| **FastMCP Tool Response (SSE Latency)** | < 35 ms | 极优 |
| **Heartbeat Overhead (HB_SEC)** | 15.0 s | 极低开销 |
